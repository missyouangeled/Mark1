## ❌ litellm/agnes-2.0-flash（已弃用 — 静默丢数据）

**2026-08-06 从 compaction / memoryFlush 移除。**

### 🔴 坑点：HTTP 200 但正文为空

实测请求（`max_tokens: 16`）返回：
```json
{"finish_reason":"length",
 "message":{"content":"","reasoning_content":"The user sent..."},
 "usage":{"completion_tokens_details":{"reasoning_tokens":16,"text_tokens":0}}}
```

- **HTTP 200，不报错**，但 `content` 是空字符串
- token 预算全烧在 `reasoning_content`，`text_tokens: 0`
- 对比 agnes-2.5-flash 同等预算下正文正常输出

### 为什么这是隐患而不只是「效果差」

它当时挂在 **compaction** 上。compaction 输入必然是长上下文，若预算被 reasoning 吃掉、正文输出为空 → **压缩结果为空 → 上下文静默丢失，且全程不报错**。

形态同 `CASE-20260706-004`（stopReason=length 死锁）；危害类型同 8-05 那个「聚合脚本静默覆盖 transcript」：**不报错、不崩溃、悄悄丢东西**。

## 🎨 volcengine-agent/doubao-seedream-5.0-lite（图生）

- **ID**：`volcengine-agent/doubao-seedream-5.0-lite`
- **端点**：`https://ark.cn-beijing.volces.com/api/plan/v3/images/generations`
- **最小尺寸**：1920x1920（API 要求 ≥ 3686400 像素）
- **可用模型**：`doubao-seedream-5.0-lite` / `4.5` / `4.0`
- **费用**：Agent Plan 套餐内
- **实测（2026-08-06）**：HTTP 200 / 18.4s / 1920x1920 出图成功

### 使用要点
- ⚠️ 必须传 `watermark: false`，否则默认带「AI生成」水印（7-29 验证）
- 2026-08-06 起已接入 `image_generate` 工具，可直接调用
- provider models 数组声明该模型时，**不能写 `output` 字段**（`additionalProperties: False`），否则 `config validate` 报 `Invalid input`

### HTTP 直调方式（工具不可用时的兜底）
```bash
curl -s --max-time 120 \
  -H "Authorization: Bearer $ARK_KEY" -H "Content-Type: application/json" \
  "https://ark.cn-beijing.volces.com/api/plan/v3/images/generations" \
  -d '{"model":"doubao-seedream-5.0-lite","prompt":"...",
       "size":"1920x1920","watermark":false,"response_format":"url"}'
```

## 📌 改模型配置的标准动作（2026-08-06 固化）

1. **先 curl 实测**目标端点 + 模型，不照抄历史结论
2. `cp` 备份 `openclaw.json`（带时间戳）
3. 用 `edit` 精确改，**绝不用 Python 直写**（CASE-20260616-002：直写导致重复键，Gateway 起不来）
4. 校验三连：JSON 语法 + **重复键检查** + `openclaw config validate`
5. 不确定字段合法性 → `openclaw config schema` 查，别猜
6. **重启 gateway 才生效**：进程启动时读配置进内存；`config get` 读磁盘，磁盘已改 ≠ 运行时已重载
7. ⚠️ **主会话内禁止 restart/stop gateway**（CASE-20260803-012 / CASE-20260706-003），交由点点执行
8. 留痕：变更流水 + install-registry + 本文档

## 🎨 litellm/agnes-image-2.1-flash（图生）

- **ID**：`litellm/agnes-image-2.1-flash`
- **用途**：文生图
- **API 网关**：LiteLLM → `https://apihub.agnes-ai.com/v1`
- **端点**：`/v1/images/generations`
- **支持尺寸**：1024x1024, 1024x1536, 1536x1024, 2048x2048
- **费用**：免费层

### 🔴 已知坑点（重要！）

#### 坑点 1：LiteLLM 管道返回格式异常
- **现象**：通过 `image_generate` 工具调用 `litellm/agnes-image-2.1-flash` 时，偶发 `LiteLLM image generation response malformed`
- **原因**：LiteLLM 管道对 Agnes 图生 API 的响应格式解析不稳定——URL 模式返回的图片链接可能被 LiteLLM 误判格式
- **触发率**：约 50%（下午 3 次成功，刚才 3 次失败）
- **绕过方法**：直接调 Agnes 原生 API

#### 绕过方案（直接调原生 API）
```bash
API_KEY=$(cat ~/.openclaw/openclaw.json | python3 -c \
  "import sys,json; print(json.load(sys.stdin)['models']['providers']['litellm']['apiKey'])")

# 生成图片
RESP=$(curl -s --max-time 120 \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  "https://apihub.agnes-ai.com/v1/images/generations" \
  -d '{
    "model": "agnes-image-2.1-flash",
    "prompt": "你的prompt",
    "n": 1,
    "size": "1024x1536"
  }')

# 提取 URL 并下载
URL=$(echo "$RESP" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d['data'][0]['url'])")
wget -q -O /path/to/output.png "$URL"
```

#### 坑点 2：不支持 base64 响应格式
- `response_format: "b64_json"` → 报错 `UnsupportedParamsError`
- 只能走 URL 模式

#### 坑点 3：URL 图片下载可能超时
- `platform-outputs.agnes-ai.space` 从国内下载偶尔超时
- 用 `wget` 比 `curl` 稳定

## 🔮 nvidia/z-ai/glm-5.1（不稳定）

- **ID**：`nvidia/z-ai/glm-5.1`
- **用途**：备选聊天模型（NVIDIA API 上的 GLM-5.1）
- **状态**：⚠️ 不稳定，不推荐日常使用

### 🔴 已知坑点

#### 坑点 1：Thinking 不支持
- `thinkingLevel="high"` → `GatewayRequestError: thinkingLevel "high" is not supported`
- **必须**在切到这个模型前先把 thinking 关掉

#### 坑点 2：偶发 incomplete terminal response
- 即使 thinking=off，也会偶发 `incomplete terminal response`
- NVIDIA API 直连测试正常（`curl` 能返回），但 OpenClaw 流式解析偶尔断连
- 可能原因：OpenClaw 的 SSE/stream 解析与 GLM-5.1 响应格式不完全兼容

#### 坑点 3：不推荐日常使用
- 稳定性远不如 deepseek-company 系列
- 如果想尝鲜，建议只做短问答，不要切主会话
