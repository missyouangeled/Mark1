# 自主决策器方案 - 最小主动行为

> 状态：方案待review
> 创建：2026-07-27

## 目标

做一个轻量小模型，根据输入特征自主决定"要不要主动跟点点聊天"。
输出0就不动，输出1就通过系统事件触发我发起对话。

## 和现有cron的区别

| | cron定时任务 | 自主决策器 |
|---|---|---|
| 逻辑 | `if 9:00 then send` | 加权求和 -> 过阈值才send |
| 触发时间 | 固定 | 不可预测，由模型算出来 |
| 本质 | 规则触发 | 自主判断 |

## 架构

```
输入特征收集器（每分钟跑一次）
    │
    ├─ 当前时间点（编码为一天中的位置）
    ├─ 距离上次对话的分钟数
    ├─ 今日已对话轮数
    ├─ 上次对话的情绪标记
    ├─ 星期几（工作日/周末）
    ├─ 最近3天平均对话频率
    ├─ 是否有pending话题（上次说了"待会儿"之类）
    │
    ▼
小模型（加权求和 + sigmoid）
    │
    ├─ score < threshold -> 输出 0（不主动）
    └─ score >= threshold -> 输出 1（触发对话）
                                    │
                                    ▼
                          openclaw system event
                          "自主决策器触发：score=X, 请跟点点打个招呼"
                                    │
                                    ▼
                            贾维斯收到后自然地发起对话
```

## 模型设计

### 最简版：线性加权

不做神经网络。就是一个加权评分：

```python
score = (
    w1 * time_score +           # 当前时间段是否是点点常聊天的时间
    w2 * gap_score +            # 距离上次对话的时长（越久分越高）
    w3 * frequency_score +      # 今日对话次数（太少分高，太多分低）
    w4 * mood_score +           # 上次对话情绪（低落时多关心）
    w5 * weekday_score +        # 工作日/周末
    w6 * pending_score +        # 有无pending话题
    w7 * trend_score            # 最近对话频率趋势
)

if sigmoid(score) >= threshold:
    return 1  # 主动触发
return 0
```

### 权重从哪来

从历史daily记录里提取：
- 点点通常什么时候主动发起对话
- 什么时间段聊天密度最高
- 聊完一次后通常隔多久再来

用现有的 `memory/daily/` 里的时间戳做训练数据。
不需要标注，就是从真实行为里统计出权重。

### 进阶版（可选，以后再说）

把线性加权换成一个3层MLP（多层感知机），输入7维，隐藏层16个神经元，输出1维。PyTorch几十行代码。但先不急，线性版跑通了再说。

## 输入特征详细设计

| 特征 | 取值范围 | 说明 |
|---|---|---|
| time_score | 0-1 | 一天中的时间映射，8:00-22:00线性映射到0.2-1.0，深夜0-7点为0.1 |
| gap_score | 0-1 | 距离上次对话分钟数，0min=0，30min=0.3，1h=0.5，3h+=1.0 |
| frequency_score | 0-1 | 今日已对话0次=1.0，1次=0.7，3次=0.4，5次+=0.1 |
| mood_score | 0-1 | 上次对话情绪标记：低落=1.0，平静=0.5，开心=0.3 |
| weekday_score | 0-1 | 周一到周五=1.0，周末=0.6 |
| pending_score | 0-1 | 有pending话题=1.0，无=0.0 |
| trend_score | 0-1 | 最近3天平均对话频率，低于均值=1.0，高于=0.2 |

## 关键参数

- **threshold**：sigmoid阈值，初始设0.6，太高不触发，太低会刷屏
- **冷却期**：触发一次后至少间隔30分钟才能再触发
- **勿扰时段**：22:00-7:00 强制输出0（除非有特殊情况）
- **每日上限**：一天最多主动触发3次

## 防刷屏机制

1. 冷却30分钟
2. 每日上限3次
3. 勿扰时段
4. 如果上一轮主动触发后点点没回，不连续触发

## 技术栈

- Python 3 + numpy（不需要深度学习框架）
- 数据存储：`~/.config/mark42/autonomy/` 下的JSON文件
- 状态文件：`state.json`（记录上次对话时间、今日触发次数、上次情绪等）
- 权重文件：`weights.json`
- 日志文件：`decisions.jsonl`（每次决策的输入和输出，便于调参）

## 部署方式

- systemd timer，每分钟跑一次检查脚本
- 脚本输出1时，通过 `openclaw system event` 注入事件到主会话
- 贾维斯收到事件后，用自然语言发起对话（不是模板消息）

## 实现步骤

1. **数据收集**：写脚本从 daily 文件里提取对话时间戳，统计出初始权重
2. **核心模块**：`autonomy.py`，输入特征 + 加权求和 + 决策
3. **状态管理**：`state.json` 记录当前状态
4. **集成**：systemd timer + openclaw system event
5. **日志**：每次决策记到 `decisions.jsonl`，便于后续调参
6. **调参**：跑一两周后根据实际触发效果调整权重和阈值

## 未来扩展
