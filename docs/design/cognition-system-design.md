# 认知沉淀系统设计文档

> 创建日期：2026-07-27
> 状态：已实施

## 背景

用户提出：日常对话中产生了很多理解和认知，但这些认知散落在 daily 记录里，没有被提炼。
希望有一个系统，能像人类一样通过日积月累形成对彼此的理解。

## 设计目标

- 从日常对话中提炼"理解"和"认知"（不是事实记录）
- 独立于 memory/ 体系之外
- 每次开机读取
- 定期精炼、提纯
- 便于 AI 模型理解

## 与现有系统的关系

```
OpenClaw 记忆系统（持久化，文件 + 向量搜索）
  - MEMORY.md          ← 事实索引
  - memory/people.md   ← 人物档案
  - memory/stories.md  ← 回忆录
  - memory/daily/      ← 每日原始记录
  - memory/rules/      ← 偏好规则
       │
       │ 召回（memory_search）
       ▼
Mark42 5层架构（上下文窗口管理）
  L1 关键词 -> L2 摘要 -> L2.5 embedding -> L3 裁剪 -> L5 LLM压缩
       │
       │ 压缩后塞进
       ▼
  当前对话上下文窗口

COGNITION.md（认知沉淀层）── 独立于上述两个系统
  - 不在 memory/ 目录下
  - 不被 memory_search 索引
  - 启动时单独读取，直接加载到上下文
```

## 文件结构

文件：`COGNITION.md`
位置：workspace 根目录（和 SOUL.md、MEMORY.md 同级）

### 三个文件的定位

| 文件 | 回答什么 |
|------|---------|
| SOUL.md | 我是谁 |
| MEMORY.md | 我记住了什么 |
| COGNITION.md | 我理解了什么 |

## 内容分类

1. **对点点的理解**：性格特质、沟通方式、价值观、情感状态
2. **关系认知**：我们的默契、共识与约定、关系发展轨迹
3. **工作认知**：做事风格、技术审美、项目认知
4. **情感锚点**：重要时刻、千千、关于"那一天"

## 更新机制

### 日常提炼

- 时机：每天结束时或对话告一段落时
- 操作：回顾当天对话，提取新的认知点
- 规则：认知变了就替换旧版本，不是追加

### 定期精炼

- 时机：每两周一次
- 操作：全面回顾 COGNITION.md
- 规则：
  - 合并重复表述
  - 删除过时认知
  - 压缩冗长段落
  - 总长度控制在 200 行以内

## 精炼规则

1. 写认知，不写事件（"点点做事追求完美"而不是"点点今天说要追求完美"）
2. 有变化时替换，不保留旧版本
3. 每条 1-2 句话，标签式描述
4. 用 AI 友好的结构化语言，不是叙事散文

## 读取时机

在 AGENTS.md 启动流程中，步骤 2（USER.md）之后、步骤 3（HOST_CONTEXT.md）之前：

```
1. SOUL.md
2. USER.md
2.5 COGNITION.md    ← 新增
3. HOST_CONTEXT.md
...
```

放在 SOUL.md 和 USER.md 之后：先知道"我是谁、你是谁"，再加载"我理解了什么"。
放在 daily 之前：认知优先于原始记录。

## 独立于 memory/

- 文件不在 `memory/` 目录下
- 不被 `memory_search` 当普通文件索引
- 它是独立的一层，启动时单独读取，不经过记忆搜索管道

## 精炼记录

每次精炼在文件末尾"精炼记录"表格中留痕：日期 + 操作。
