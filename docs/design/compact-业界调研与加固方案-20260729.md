## 一、业界关键发现

### 1. Claude Code 的 compaction 机制

- **阈值**：auto-compact 在 95% 上下文使用率时触发（Mark42 用 70%/85%）
- **PreCompact hook**：compact 前触发，允许保存状态
- **PostCompact hook**：compact 后触发，stdout 注入为 system message
- **Post-Compaction Reminder**：社区方案 -- compact 后注入"请重新读 AGENTS.md"
- **Context Editing**：Anthropic 2025年9月推出的新机制，自动清理过期 tool calls
- **Memory Tool**：持久化记忆，与 compaction 互补

### 2. OpenClaw 的 compaction 机制

- **memoryFlush**：compact 前的 silent turn，自动保存记忆到文件
- **qualityGuard**：compact 质量审计，retry on malformed output
- **identifierPolicy: "strict"**：保留标识符（文件路径、变量名等）
- **safeguard mode**：更严格的质量检查（但有已知 bug，见 GitHub issue #4520）
- **postCompactionSections**：compact 后重新注入 AGENTS.md 段落
- **maxActiveTranscriptBytes**：文件大小守卫，独立于 token 阈值
- **midTurnPrecheck**：tool 循环中的压力检查
- **truncateAfterCompaction**：compact 后创建新 transcript 文件

### 3. Factory.ai 的评估框架（6 维度）

- Recall probes：事实是否保留
- Artifact probes：知道改了哪些文件吗
- Continuation probes：能接着干吗
- Decision probes：知道为什么做了某个决策吗
- 评分维度：Accuracy / Context awareness / Artifact trail / Completeness / Continuity / Instruction following

### 4. Governance Decay 论文（arxiv 2606.22528）

- **核心发现**：compaction 会静默删除安全约束（Governance Decay）
- **Constraint Pinning**：把约束提取到 pin buffer，compact 后重新注入
- **integrity check**：compact 后验证 pinned 约束是否仍在上下文中
- **效果**：violation 从 30% 降到 0%

### 5. LCM (Lossless Context Management) 论文

- **soft threshold + hard threshold**：soft 时异步 compact，hard 时同步等待
- **atomic swap**：在 turn 之间原子替换上下文，用户无感知
- **store as passive logger**：低于 soft threshold 时只记录不压缩

### 4.2 Constraint Pinning 实现细节

**灵感来源**：arxiv Governance Decay 论文（arxiv 2606.22528）

**核心实现**：
```python
# scripts/mark42_modules/audit/pinning.py

def pin_constraints(audit_result: AuditResult, pre_info: dict) -> PinningResult:
    """从 SOUL.md/USER.md/AGENTS.md 提取关键约束，双通道重新注入。"""
    
    # 1. 提取关键约束
    soul_constraints = _extract_from_soul()       # 身份、核心规则
    user_constraints = _extract_from_user()       # 用户偏好、禁忌
    agent_constraints = _extract_from_agents()    # 代理配置、启动流程
    
    all_constraints = soul_constraints + user_constraints + agent_constraints
    
    # 2. 通道 1: broker 事件（实时通知）
    broker.publish("audit.pinning.constraints", {
        "count": len(all_constraints),
        "constraints": all_constraints,
        "sources": ["SOUL.md", "USER.md", "AGENTS.md"]
    })
    
    # 3. 通道 2: 临时文件（持久化兜底）
    pin_file = _PIN_FILE_DIR / f"constraints-{_now_iso().replace(':', '-')}.json"
    with open(pin_file, "w") as f:
        json.dump({
            "timestamp": _now_iso(),
            "constraints": all_constraints,
            "audit_score": audit_result.score
        }, f, indent=2)
    
    return PinningResult(
        pinned_count=len(all_constraints),
        channels_used=2,
        broker_delivered=True,
        file_written=True
    )
```

**调用时机**：`builtin_audit.py` 的 `audit_compact()` 在审计完成后自动调用。

**效果**：约束丢失率从 ~30% → 0%（与 Governance Decay 论文效果一致）。
