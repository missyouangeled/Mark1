## 二、🔴 第一个决定性发现：ScreenSpaceOverlay 下 3D 粒子必被 UI 盖住

### 实测数据

```
Canvas.renderMode = ScreenSpaceOverlay
Canvas.sortingOrder = 0
Canvas.worldCamera = NULL
```

### 联网查到的原理（官方论坛 frame debugger 实测结论）

| Canvas 模式 | 渲染顺序 | 粒子能否盖在 UI 上 |
|------------|---------|-----------------|
| **ScreenSpaceOverlay** | 所有场景物件先渲染 → Canvas 最后 | ❌ **永远不能** |
| ScreenSpaceCamera | Canvas → 粒子在其后 | ✅ 可以 |
| WorldSpace | 同上 | ✅ 可以 |

### 这解释了上午那个未解之谜

上午我在机库背景加的 3D 火焰粒子，`particleCount: 54` 确实在喷，但**画面里看不见**。
当时我判断是「位置不在镜头可见范围」——**错了**。真因是渲染顺序注定看不见。

### 我没有采纳搜索给的常规解法

搜索结果建议「把 Canvas 改成 Screen Space - Camera」。**我拒绝了**：
那会改变整个菜单的缩放与布局，风险远超「加一个效果」的量级。

→ **改走 UI 层内部叠加**：`RawImage` + 序列帧 flipbook，完全在 UI 渲染体系内，不碰排序。

## 四、🔴 第二个决定性发现：图集是 8×8，不是 4×4

### 我的错误猜测

第一版我按 `uvRect = (0, 0.75, 0.25, 0.25)` 切，即假设 4×4 网格。
出图后点点反馈「火焰太小」，我一开始以为是尺寸参数不够大。

### 实测方法：把图集导出来肉眼看

不能靠猜。写 C# 用 `Graphics.Blit` → `RenderTexture` → `ReadPixels` 绕过
compressed/non-readable 限制，把透明区域合成到深色底上导出 PNG，回传后用 `image` 工具看：

| 图集 | 网格 | 火焰形态 | 占单格面积 |
|------|------|---------|-----------|
| `AF_Fire_Sequence_01` | **8×8** | 小火星生灭 | 10-25% |
| `AF_Fire_Sequence_02` | **8×8** | 竖直摇曳火苗 | 30-50% ← **选它** |
| `AF_Fire_Sequence_06` | **8×8**（2048²） | 大火球+浓烟 | 后期 80%+ |

### 「火焰太小」的真正根因

**8×8 图集按 4×4 切 → `uvRect` 0.25 实际取到「4 格拼在一块」**，
其中火焰只占中心一小部分，四周全是空白。

**不是尺寸没调够，是切错了。** 改成 `1/8 = 0.125` 后火焰立刻正常。

## 五、实现方案

### 新建脚本 `Assets/Scenes/Interface/UI/Scripts/UIFlipbookFire.cs`

```csharp
// 核心逻辑
void Update() {
    int total = frameCount > 0 ? frameCount : columns * rows;
    _t += Time.unscaledDeltaTime * fps;
    Apply(((int)_t) % total);
}
void Apply(int idx) {
    float w = 1f / columns, h = 1f / rows;
    int cx = idx % columns, cy = idx / columns;
    float y = 1f - h * (cy + 1);          // 图集第0帧在左上，UV原点在左下，y 需翻转
    _raw.uvRect = new Rect(cx * w, y, w * Mathf.Max(1, tileX), h);
}
```

暴露参数：`columns/rows`(8×8)、`fps`(24)、`frameCount`、`alpha`(0.85)、`tint`、**`tileX`**。

**`tileX` 是第二轮加的**：单束火苗太窄铺不满卡片宽度，
`tileX=3` 让 uvRect 宽度 ×3，靠纹理 wrapMode=Repeat 平铺出三束火苗。

### 物件结构（最终态）

```
Canvas/Main_Panels/HOME/Content/SliderInfo
└─ FX_Fire_Overlay
   ├─ RectTransform  anchorMin(0,0) anchorMax(1,0.34)  ← 占父级底部 34%
   ├─ RawImage       AF_Fire_Sequence_02  alpha 0.85  raycastTarget=false
   └─ UIFlipbookFire 8×8=64帧  fps 24  tileX 3
```

`raycastTarget=false` 很重要 —— 否则会挡住底下卡片的鼠标事件。
`SetAsLastSibling()` 保证画在 SliderInfo 图像之上。

## 六、🔴 踩到的五个坑

### 1. assembly reload 把 `CanvasGroup.alpha` 打回 0 → 整个 UI 消失

改脚本后 `editor refresh` 触发编译，重连后截图发现**画面只剩 3D 机库，菜单全没了**。

**最阴的地方：数据层全是正常的。**
```
Canvas       active=True
Main_Panels  active=True
HOME         active=True      ← 看起来没问题
SliderInfo   active=True
Overlay      active=True
```

我一开始怀疑是截图工具的问题，换了截图方式再试还是没有。
逐级查 alpha 才看到：

```
Canvas/Main_Panels        alpha=1
Canvas/Main_Panels/HOME   alpha=0    ← 罪魁祸首
```

菜单的面板淡入是 Animator 驱动 CanvasGroup 的，assembly reload 把运行时状态打回初始值 0，
而重新播放的逻辑没跑。

**修法**：没有手改 alpha 糊过去，而是**干净重启 Play** 让菜单走自己的初始化 → `alpha=1` 恢复。

**教训：`activeInHierarchy=True` 不代表看得见。UI 还要查 CanvasGroup.alpha / Image.enabled / scale。**

### 2. 运行时建的物件，退出 Play 就没了

第一版我在 Play 模式下建 Overlay，退出后 `Overlay存在=False`。
**必须在编辑模式（`isPlaying=False`）建 + `scene save`** 才持久化。

### 3. `ScreenCapture.CaptureScreenshot` 抓不到 ScreenSpaceOverlay 的 UI

用它截出来的图**只有 3D 场景，没有任何 UI**。
必须用 Bridge 的 `debug.screenshot`（`mode=screencapture`，走主动渲染）。

（补充上午已知的另一条：`CaptureScreenshot` 在**非 Play 模式下根本不写盘**，依赖渲染帧循环。）

### 4. `script create` 不能覆盖已存在的文件

报 `Script already exists... Use 'update' action`。
绕法：`code execute` 里 `File.WriteAllText` + `AssetDatabase.ImportAsset`。

写完**没有信返回值**，用反射查了字段列表确认 `tileX` 真编译进去了：
```
fields: columns rows fps frameCount alpha tint tileX
```

### 5. `reflect search` 查不到项目自己的脚本

`reflect search "UIFlipbookFire"` → `count: 0`，但脚本明明编译成功、零错误。
**原因：reflect 扫的是 Unity 内置程序集，不含 Assembly-CSharp。**
验证项目脚本要用：
```csharp
System.Type.GetType("UIFlipbookFire, Assembly-CSharp")
```

## 七、⚠️ 我的两个失误（点点指出「火焰位置弄错了」）

### 失误 A：火焰位置放错了

点点要「**在展开出来的新选项卡前**叠加火焰」。
我放在了 `SliderInfo`（右侧那块常驻的信息卡片）底部 1/3。

从最终视频看，火焰实际落在 **NEWS & EVENTS 卡片下沿 / COMMUNITY 栏上沿**的交界处，
而不是「hover 展开的那个选项卡」上。

**根因**：我把「hover 后展示出来的新选项卡」理解成了 `SliderInfo`，
但 `SliderInfo` 是**一直都在**的右侧信息面板，并不是 hover 才出现的东西。
hover 真正改变的只是左侧按钮自身的高度（25→70）。

**下次要先确认**：hover 前后做一次 hierarchy diff，看**到底哪个物件是新出现/变化的**，
而不是凭画面观感猜。

### 失误 B：ffmpeg 裁切来回改了四遍，且一开始靠猜

前三次 crop 参数全是估的。看图反馈还前后矛盾 ——
同一次裁切先说「根部被下边缘切」，改了之后又说「根部被上边缘切」。

**矛盾的反馈本该让我立刻停下重新诊断**（真因是火焰被 COMMUNITY 那块 UI 挡住下半截），
但我又调了一轮裁切，原地打转。

第四次才想到用 `GetWorldCorners` 读精确坐标：

```
火焰层屏幕坐标: 左下=(1546,119) 右上=(1990,395)
→ PNG 裁切(原点左上): x=1546  y_top=707  w=444  h=276
```

我第一次裁的 `y=130`，**实际该是 707 —— 差了 577 像素。**

**教训：能实测的别猜。早两分钟读数据就不用绕这一圈。**
（与今日早间「误读累加日志」「单点采样误判 timer」完全同源。）

## 八、录制动态视频的完整流程

静态图看不出火苗窜动，用 ffmpeg 合成短视频。

### 关键点

1. **每帧都要重新锁 hover** —— UI 自身逻辑会把展开状态重置
2. **必须用 Bridge `debug.screenshot`** —— `CaptureScreenshot` 抓不到 Overlay UI
3. 截图落在 Windows，需 `code execute` + `WebClient` 回传到 VM

### 脚本 `scripts/unity-record-ui-effect.sh`（30 帧）

```bash
for i in $(seq -f "%03g" 1 30); do
  # ① 锁 hover（每帧都要）
  timeout 40 $M code execute --no-safety-checks -f /tmp/lock_hover.cs
  # ② Bridge 截图，取回 Windows 文件名
  SHOT=$(curl -s -X POST $BRIDGE -d '{"tool":"debug.screenshot","arguments":{}}')
  NAME=$(echo "$SHOT" | python3 -c "...basename...")
  # ③ code execute 回传
  timeout 60 $M code execute --no-safety-checks -f /tmp/up_seq.cs
done
```

⚠️ 接收端会把文件名里的 `/` 替换掉（防目录穿越），所以传 `seq/frame_001.png`
会落成 `seq_frame_001.png` —— 直接用扁平命名 `seqframe_001.png`。

### 合成

```bash
# 全屏版
ffmpeg -y -framerate 12 -pattern_type glob -i 'seqframe_*.png' \
  -vf "scale=1400:-2:flags=lanczos" -c:v libx264 -pix_fmt yuv420p -crf 22 \
  -movflags +faststart fire_edge_full.mp4

# 特写版（坐标来自 GetWorldCorners，不要猜）
ffmpeg -y -framerate 12 -pattern_type glob -i 'seqframe_*.png' \
  -vf "crop=604:436:1466:627,scale=860:-2:flags=lanczos" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -movflags +faststart fire_edge_card.mp4
```

30 帧 @ 12fps = 2.5 秒。

### 自检环节（做对了的地方）

合成后**先自己抽帧拼图用 `image` 工具看过**，确认内容对才发给点点：

```bash
ffmpeg -y -i fire_edge_card.mp4 -vf "select='eq(n\,0)+eq(n\,10)+eq(n\,20)',tile=3x1,scale=1100:-2" \
  -frames:v 1 verify.jpg
```

⚠️ `image` 工具对大图会超时（1.3MB PNG 超 60s），**先转小 jpg 再看**。

## 十、可复用清单（下次做 UI 特效直接抄）

### 决策树

```
要在 UI 上加特效？
├─ 先查 Canvas.renderMode
│   ├─ ScreenSpaceOverlay → ❌ 3D 粒子无效，必须走 UI 层（RawImage/Image + 序列帧）
│   └─ ScreenSpaceCamera/WorldSpace → 3D 粒子可行，配 sortingLayer
├─ 找现成资产（本项目 1913 个材质、Fire 13 / Flame 8 / 整套序列帧）
├─ 图集网格必须实测（导出来看），不要猜行列数
└─ 编辑模式建 + scene save，不要在 Play 里建
```

### 本项目现成火焰资源

| 用途 | 资源 |
|------|------|
| 竖直摇曳小火苗 | `Assets/AB/Pool/Material/Type_Fire/Fire_Sequence_02/AF_Fire_Sequence_02.png`（8×8） |
| 小火星生灭 | `Fire_Sequence_01/AF_Fire_Sequence_01.png`（8×8） |
| 大火球+浓烟（笼罩用） | `Fire_Sequence_06/AF_Fire_Sequence_06.png`（8×8, 2048²） |

### 参数调节对照

| 想要 | 改什么 |
|------|-------|
| 火焰更高 | `anchorMax.y` 0.34 → 0.4~0.45 |
| 火苗更密（填满横向） | `tileX` 3 → 4/5 |

// 再 scene save
