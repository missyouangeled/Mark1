## 08:44-09:07 timer 追到底 —— 今天最严重的问题（CASE-017）

### 现象

`openclaw-frontstage-guardian` / `openclaw-health-collector`：`is-enabled` = enabled，`is-active` = active，**但 `list-timers` 的 NEXT 列为 `-`**，service 最后运行 **08-05 17:54**，当天一次没跑。

**前台假死检测 + CPU 过载自动响应两道防线空置约 12 小时。**

### 根因（man systemd.timer 证实，不是猜的）

三条权威定义：
1. `OnBootSec=` = 相对**机器开机**
2. `OnStartupSec=` = 相对 **service manager 启动**；官方明说对 per-user manager 特别有用，因为「用户级 manager 通常在**首次登录时才启动，而非开机时**」
3. `Persistent=` = 「**only has an effect on timers configured with `OnCalendar=`**」

这批是 user 级 timer 却用了 `OnBootSec`。秒级时间线：

| 事件 | 时刻 | 相对开机 |
|---|---|---|
| 机器开机 | 07:30:51 | 0s |
| user manager 启动 | 07:32:17 | **+86s** |
| `OnBootSec=90s` 触发点 | 07:32:21 | +90s |
| timer 单元启动 | 07:32:25 | **+94s** |

**timer 启动时，它的触发时刻已经过去 4 秒。** 死锁链：触发被跳过 → `Persistent` 无 `OnCalendar` 故无效、补不回 → service 从未激活 → `OnUnitActiveSec` 拿不到锚点 → **永久卡死**。

与 CASE-20260803-014 同一种病：**看起来在工作，实际救不了任何东西。**

### 🔴 问题比报的大：全体 timer 都在雷区

清点 9 个 timer，**全部同一缺陷写法**，零个用 `OnStartupSec`，零个有 `OnCalendar`。今天没死的只是「赶上了」：

| timer | 余量（相对 86s） |
|---|---|
| frontstage-guardian / health-collector | **4s → 已阵亡** |
| task-scheduler / resume-watch / session-backup | 34s |
| **mark42-watchdog** / autonomy | **34s** |
| lifecycle-maintainer / session-size-watcher | 94s |

**watchdog 也在里面** —— 那是负责拉起守护进程的自愈机制本身。开机稍慢就会成批阵亡。

### 修法

三重保障（OR 关系，不依赖单一锚点）：`OnStartupSec=90s` + `OnUnitActiveSec=<周期>` + `OnCalendar=<兜底>`。

新建 `scripts/harden-user-timers.sh`（默认 dry-run，`--apply` 才写入）统一加固另外 6 个。

### 🔴 修复中踩到第二个坑

**`OnBootSec=` 空串会重置整个 monotonic timer 列表**，不只清一项 —— 主文件的 `OnUnitActiveSec` 被一起清掉。必须在 drop-in 显式重申。

frontstage-guardian 当时没暴露，纯属巧合：`relax-interval.conf` 按字母序在 `fix-` 之后加载又给加回来了。**不能依赖巧合。**

### 🔴 我误判过一次，还向点点报告了错结论

我看到 `SubState=running` 而 service 已 `dead`，判定「修法没生效、还有第二个独立问题」并报告了。

**这个判断是错的。** `running` 是 timer 触发 service 期间的**正常中间态**：`waiting → running（执行中，不排下次）→ waiting（排下次）`。我恰好在那一两秒的执行窗口内做了单点采样。

**教训：判断周期性任务健康，必须连续多周期观察 + 数实际执行次数，不看瞬时状态。** 这与今天前三个「两端不同源」的错误同源。

## 今日方法论教训（四条同源）

> 共性都是：**比较/验证的两端不同源、不同口径、或采样时机错**。

1. `stat` 文件字节数 vs Python `len()` 字符数 → 中文 UTF-8 占 3 字节，误判文件变小
2. `config get` 读磁盘 vs 进程内存 → 误判配置已生效
3. `config validate` 校验格式 vs 运行时能力 → 误判功能可用（最隐蔽，每步都给绿灯）
4. 单点采样瞬时 `SubState` vs 连续观察执行次数 → 把正常中间态误判为故障

## 13:20-13:40 Unity 连接栈收编为 systemd 模块

### 起因：意外重启后 Unity 全断

点点说「刚才意外重启了，看看还能接上刚才的步骤么」，同时发来 Unity 插件配置面板截图，
要求告诉他怎么填地址和端口。

看图 + 查端口后定位到**两个原因叠一起**：

1. **Bridge 服务根本没在跑**（27182 无进程无端口）—— 重启把 nohup 裸进程带走了
2. **他截图里 Gateway URL 填的是 18789**（Gateway 端口），Unity 插件连它必报
   `An error occurred while sending the request`。应填 27182

告诉他改两处：URL 改 27182、API Token 清空（Bridge 的 `checkAuth` 无 header 时跳过验证）。
其余（Auto Connect / Heartbeat 30 / MCP Bridge Port 27182 / Security 三项）全部保持不动。

→ 他改完连上了。

### 第二条：MCP 也是同一个病

他接着问 MCP 点连接不行「是不是没开监听」。**他判断对了** —— 8080 同样无进程无端口。
拉起后验证 `✅ Connected` + Unity 实例注册成功：
```
Plugin registered: 2026-04-28 (16e644b73f34b342)
Registered 35 tools for session b4d185c2...
```

顺带记一个实测特性：**MCP 启动比 Bridge 慢，6 秒时端口还没 listen，约 8-14 秒才绑上**。
`Type=simple` 下 systemd 报 Started 只代表 fork 成功，不代表已 listen。

### 点点的要求

> 「把 Unity 连接这块的两个都写成一个模块，并且开机自动启动，做成一个补丁的那种，
> 删掉就都删掉了，开启就都开启。」

### 做法

```
openclaw-unity.target                ← 总开关
├─ openclaw-unity-bridge.service     :27182
└─ openclaw-unity-mcp.service        :8080
```

关键是两个字段配对：
- `WantedBy=target` → start target 时成员被拉起（开就都开）
- `PartOf=target` → stop target 时成员跟着停（关就都关）
- 只 enable target，不单独 enable 成员 → 避免半启动状态

统一入口 `scripts/unity-stack-patch.sh`，默认 dry-run，对齐今早 harden-user-timers.sh 的风格。

### 验收（做了实际调用，不看灯）

遵守今早刚立的硬规矩：`is-active` 全绿 ≠ 能用。

| 项 | 结果 |
|---|---|
| 开就都开 / 关就都关 | ✅ 各测一轮，端口正确 listen / 正确释放、零残留进程 |
| 开机自启 | ✅ 三单元 enabled + `Linger=yes` 确认 |
| 崩溃自愈 | ✅ `kill -9` Bridge → 8 秒复活，pid 7150→7231 |
| `systemd-analyze verify` | ✅ 零告警 |
| Bridge 真命令 | ✅ `debug.hierarchy` 读回 Canvas 全树；`scene.getActive` → `Main.unity` rootCount 7 |
| MCP 真命令 | ✅ `reflect search GameObject` → 14 类型；`scene hierarchy` → total 7 |
| **交叉印证** | ✅ 两条通道 7 == 7，互相对得上 |

### 两个坑

1. **安装脚本必须先 `pkill` 裸进程**，否则 service 因端口被占启动失败。
   代价是已连的 Unity 会短暂掉线 —— 我提前告知了点点。
   实测 MCP 自动重连，**Bridge 需手动点一次 Connect**（Auto Connect 只在启动时生效，
   掉线后不会自己重注册）。这条是意外收获，写进指南了。
2. **`Documentation=` 不能用中文路径**：systemd 报 `Invalid URL, ignoring`，
   不影响运行但污染 verify 输出。改成注释形式后恢复零告警。
