### 根因
我在 8:49 跑 `systemctl --user restart mark42-bootstrap mark42-engine-daemon mark42-armor-guard mark42-watchdog.timer` 想一次性 restart 所有守护。**但 watchdog.timer 的 `RefuseManualStop=yes` 让 restart 失败**——timer 状态被卡在 dead。

- **`RefuseManualStop` 会让 `restart` 也失败**（restart = stop+start）
- **批量 restart 守护时不要包含 timer**——timer 要单独 enable
- **install.sh 应该 `enable --now`** 不只是 `enable`，否则新装完不能立刻 active
- **防御措施有副作用**：加 `RefuseManualStop` 是为了防 8:30 那种 reload 链式 stop，但代价是 restart 命令不再可用——需要权衡

## 09:03 稳定性强化设计讨论（4 候选方案分析）

### Q1: 24 次 reload 触发源

### Q2: bash 主动记录能记录当前会话命令吗？
**不能完整记录**。
- bash history **只覆盖 interactive shell**（终端主动敲的命令）
- exec 工具跑的非交互 bash **不记 history**（Linux 设计）
- **可补**：PROMPT_COMMAND 把 interactive 命令追加到 daily log
- **不覆盖**：OpenClaw 内部 exec、systemd timer、cron 跑的命令
- **结论**：PROMPT_COMMAND 是**有价值的"小补丁"**（不重），但**daily 主动记仍是主路径**——点点坚持的是对的

### Q3: "守护悄悄死掉"详细影响

**L0 立即（死 1 分钟内）**：
- armor-guard 死 → mark42 不自动压缩（但你上下文 5.9%，几个月不急）
- engine-daemon 死 → 4 个循环停（context-guard / health-watch / memory-index / model-fallback）
- watchdog 死 → 没人拉起死的 daemon

**L1 累积（死 1 小时到 1 天）**：

- L1.2 日志不轮替 → broker events 涨到 10MB 撑爆磁盘

**L2 长期（死 1 周以上）**：
