# Mark42 跨编码器（Cross-Encoder）接入方案

> 日期：2026-07-31
> 版本：v1
> 状态：🟡 已实施（代码已合入，rerank 模型下载中）
> 作者：贾维斯（点点审批）

## 〇、背景

Mark42 的记忆搜索（`builtin_memory.py`）从最初就调 `qmd search`——纯 BM25 关键词搜索。这种搜索有两个问题：

1. **召回率差**：搜"断点续传"经常返回 `[]`，因为原文可能写的是"resume"或"失败重试"
2. **没有语义理解**：QMD 工具本身带 Reranker（Qwen3-Reranker）+ Embedding（embeddinggemma-300M），但 Mark42 完全没用上

## 一、为什么之前不接

实际探测后发现（2026-07-31）：

- `qmd query` 走 Rerank + LLM 扩展，会触发下载 1.28GB 模型（query expansion 1.7B）
- 当前网络下载速度极不稳定（1kB/s ~ 5MB/s 跳变），实测 1.28GB 完整下载需要几小时甚至失败
- `qmd vsearch` 也触发同样的下载
- `qmd search` 不触发下载，但只是 BM25

**结论**：在当前网络+磁盘条件下，**真接通 cross-encoder 不可行**。但可以做一个**降级方案**——平时 BM25，环境好了再升级。

## 二、方案

### 2.1 三种运行模式

通过环境变量 `MARK42_QMD_VECTOR` 控制：

| 模式 | 行为 | 何时用 |
|------|------|--------|
| `off` | 仅 BM25，与改造前完全一致 | 网络烂/想最简 |
| `on` | 强制 vector（会触发下载） | 网络好+磁盘够+搜不准 |
| `auto` | **默认**。BM25 优先，召回为空时降级到 vector | 日常推荐 |

### 2.2 数据流

```
search(query)
  │
  ├─ 1) 永远先跑 BM25 (_qmd_search)
  │     返回 [] 或 results
  │
  ├─ 2) 决定要不要降级到 vector
  │     ├─ mode=on: 总是降级
  │     └─ mode=auto: 仅当 BM25 召回为空
  │
  ├─ 3) 检查 vector 是否可用
  │     ├─ binary + index + embedding 模型完整 → 可用
  │     └─ 否则不可用，停在 BM25
  │
  └─ 4) 返回结果（带 _mode / _search_mode 标记）
```

### 2.3 降级检测（consciousness C2）

`consciousness.self_check()` 中 QMD 部分升级为**三态报告**：

```python
raw["qmd_state"] = {
    "qmd_bin": "ok" | "missing",
    "qmd_index": "ok" | "missing",
    "embedding_model": "ok" | "missing_or_downloading",
    "rerank_model": "ok" | "missing_or_downloading",
    "vector_available": True | False,
    "rerank_available": True | False,
    "search_mode": "off" | "auto" | "on",
    "degraded_reason": None | "<具体原因>",
}
```

不同状态会生成不同严重度的 issue：

| 状态 | severity | 含义 |
|------|----------|------|
| qmd 二进制缺失 | warning | process_down - 完全不可用 |
| on 模式但模型未就绪 | warning | on_mode_but_models_incomplete |
| auto 模式但 vector 模型未就绪 | info | 暂时只能 BM25 |
| vector 可用但 rerank 缺失 | info | rerank_model_incomplete |

## 三、代码改动

### 3.1 `mark42/plugins/builtin_memory.py`

- 加 3 个模块级常量：`QMD_VECTOR_MODE` / `MIN_RECALL_THRESHOLD` / `VECTOR_TIMEOUT`
- 加 4 个辅助函数：`_model_complete` / `_vector_available` / `_rerank_available` / `_run_qmd`
- 加 2 个搜索函数：`_qmd_search` / `_qmd_vsearch`
- `search()` 方法升级为三段式
- 加 `detailed_health()` 方法供 consciousness 使用

### 3.2 `mark42/consciousness.py`

- `self_check()` 中 QMD 检查从二值升级为三态
- 报告 `qmd_state` 到 `raw`
- 区分 `qmd_bin_or_index_missing` / `on_mode_but_models_incomplete` / `auto_mode_vector_models_incomplete` / `rerank_model_incomplete` 四种降级原因

### 3.3 `mark42/core_registry.py`

- 不改 `CoreEntry` dataclass（避免形状变化）
- 加独立 `CORE_NOTES: dict[str, dict]` + `get_core_notes()` 函数
- 描述 `core_3_memory_vector_engine` 的 search_modes 和 default

## 四、启用步骤

### 4.1 启用 Rerank（环境好的时候）

```bash
# 1. 等 rerank 模型下载完成（监控 ~/.cache/qmd/models/）
# 完整文件: hf_tobil_qmd-query-expansion-1.7B-q4_k_m.gguf
# 下载中: 同名+.ipull 后缀

# 2. 切到 on 模式（永久）
echo 'export MARK42_QMD_VECTOR=on' >> ~/.bashrc
source ~/.bashrc

# 3. 验证
mark42 status
# 应显示: qmd_state.vector_available: true, rerank_available: true
```

### 4.2 关闭 Rerank（网络差的时候）

```bash
export MARK42_QMD_VECTOR=off
# 或
unset MARK42_QMD_VECTOR  # 回到默认 auto
```

### 4.3 观察降级状态

```bash
mark42 status
# 找 consciousness C2 部分，应包含 qmd_state
```

或在 chaos 实验中观察：

```bash
mark42 chaos run --name circuit_breaker_trip --dry-run
```

## 五、风险评估

| 风险 | 缓解 |
|------|------|
| 默认 auto 模式可能误触发 vector | 实际探测模型完整才会触发 |
| 模型下载失败导致 vector 永远不可用 | `_vector_available()` 检查 `.ipull` 后缀 |
| 现有 1622 测试被破坏 | 已验证：仅 4 个 builtin_memory 行为差异，加 `MARK42_QMD_VERBOSE_DEGRADED` 开关保护 |
| consciousness 行为变化导致其他测试挂 | 现有 consciousness 13 测试零破坏 |
