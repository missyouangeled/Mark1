## #1 Cross-encoder 接入方案

### 现状（已搜过）
- 底层 qmd 工具：自带 Reranker（Qwen3-Reranker）+ Embedding（embeddinggemma-300M）
- 但 query expansion 模型 1.28GB 在 `~/.cache/qmd/models/` 下了一半（22.84%），**当前网络下不完**
- Mark42 `builtin_memory.py` 现在调的是 `qmd search`（纯 BM25 关键词），召回差（"断点续传" 搜出 `[]`）
- `qmd vsearch` 和 `qmd query` 都会触发模型下载，**当前网络不可用**

### 设计原则
**不写假接通代码**。Mark42 的认知原则：召回层只负责"用现有能用的能力"，不假装有 rerank。

### 改动清单

#### 改动 1：builtin_memory.py — 加配置开关

**位置**：`mark42/plugins/builtin_memory.py`
**改动**：加 3 个常量 + 1 个降级逻辑

```python
# 开关配置（从 env 或 config.toml 读）
QMD_USE_VECTOR = os.environ.get("MARK42_QMD_VECTOR", "auto")  # auto/on/off
QMD_DOWNLOAD_GRACE_HOURS = 24  # 模型未下完超过这个时间才报降级

# search() 改造
def search(self, query, top_k=5):
    # 1) 默认走 BM25 search（快、不下载）
    result = self._qmd_search(query, top_k)
    
    # 2) 如果开了 vector 且 recall=0，降级到 vsearch
    if not result and self._vector_enabled():
        result = self._qmd_vsearch(query, top_k)
        result = self._mark_degraded(result, "vector_fallback")
    
    # 3) 如果 query 召回仍 < threshold，标 cross-encoder 不可用
    if len(result) < MIN_RECALL:
        result = self._mark_degraded(result, "low_recall")
    
    return result
```

**新增方法**：
- `_vector_enabled()` — 检查开关 + 检查模型是否完整
- `_qmd_vsearch()` — 调 `qmd vsearch --json`（带超时）
- `_mark_degraded()` — 在结果里加 `_degraded: true, _reason: "..."`

## #2 Chaos 实验扩充方案

### 现状（已搜过）
- `chaos_engine.py` 有 7 个实验：kill_engine / kill_armor / fill_disk / network_latency / high_context / circuit_breaker_trip / consciousness_degraded
- 都是"破坏性"实验，没有"亚健康"类
- 测试文件：`test_chaos_engine.py` + `test_builtin_chaos.py`

### 新增 4 个实验

#### 实验 8：memory_leak（内存泄漏）
- **setup**：准备一个常驻进程（如 `python3 -c "while True: x.append('x'*1024*1024)"`）
- **execute**：跑 5 分钟，每 30s 记录 RSS
- **verify**：检测 RSS 增长率 > 阈值 → 标记异常
- **cleanup**：kill 进程
- **测试**：dry-run 必须返回 0，验证不会真泄漏

#### 实验 9：cpu_spike（CPU 飙高）
- **setup**：准备 4 个 `yes > /dev/null` 进程
- **execute**：跑 30s
- **verify**：检测 load average > 4
- **cleanup**：kill all
- **测试**：验证能正常启动/清理

#### 实验 10：config_corruption（配置损坏）
- **setup**：备份 `~/.config/mark42/config.toml` 到 `/tmp/`
- **execute**：写入垃圾内容（如 `"= = = invalid = = ="`)
- **verify**：尝试 mark42 status 应能优雅降级（不应崩）
- **cleanup**：恢复原配置
- **测试**：验证配置恢复后能正常启动

#### 实验 11：process_zombie（进程僵死）
- **setup**：启动一个会 hang 住的 daemon（如 `cat | cat` 死锁）
- **execute**：观察 10s
- **verify**：检测子进程存在但 CPU=0 且无响应
- **cleanup**：kill -9
- **测试**：verify 阶段要能识别僵死状态

### 改动清单

#### 改动 1：chaos_engine.py — 4 个新实验函数
每个实验遵循 4 阶段框架：

```python
        dry_run=dry_run,

        execute=self._execute_<name>,
        verify=self._verify_<name>,
        cleanup=self._cleanup_<name>,
    )
```

#### 改动 4：test_builtin_chaos.py — 注册到 plugin

### 风险评估
- **中风险**：实验 10/11 涉及真实系统操作（写文件、杀进程）
- **缓解**：所有实验**默认 dry_run=True**，必须 `--execute-now` 才真跑（已实现）
- **缓解**：实验 10 强制 backup + restore 流程
- **缓解**：实验 11 用 pgrep 找进程，**绝不杀用户进程**
